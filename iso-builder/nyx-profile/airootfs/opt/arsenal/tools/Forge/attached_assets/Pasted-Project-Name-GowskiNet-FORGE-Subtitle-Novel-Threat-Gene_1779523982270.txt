CORE ENGINE — How FORGE works:
Step 1 — Ingestion:
You feed FORGE raw material. It accepts anything:

Paste CVE description — FORGE extracts the vulnerability pattern
Paste malware analysis report — FORGE extracts behavioral patterns
Type natural language description — "a technique that uses DNS to exfiltrate data while looking like normal traffic"

Step 2 — Analysis:
FORGE analyzes everything you fed it:

Extracts techniques — what attack primitives are present
Maps to MITRE ATT&CK — which documented techniques does this use
Identifies patterns — timing, encoding, protocol usage, evasion methods
Detects signatures — what would current security tools flag
Finds gaps — what parts of this technique are underdeveloped or could be extended
Rates sophistication — how advanced is the existing code
Identifies dependencies — what tools, libraries, system features does it rely on
Finds the core logic — strips away everything except the fundamental technique
Visual analysis map — shows all extracted components as a relationship graph

Step 3 — Mutation and Generation:
The core of FORGE. Seven mutation engines running in parallel:
Engine 1 — Code Splicing:
Takes technique components from multiple inputs and combines them into one working script. If you fed it a port scanner and a credential stuffer — it might generate a tool that scans for open services and immediately attempts credential stuffing against found services, all in one automated chain. The combination might not exist anywhere documented.
Engine 2 — Logic Mutation:
Takes existing working code and rewrites how it achieves its goal. Same outcome, completely different implementation. Like how malware authors rewrite their code every release to evade signature detection. Generates variants that are functionally identical but look completely different to scanners.
Engine 3 — Cross Domain Fusion:
Combines techniques from completely different attack domains. WiFi technique fused with web attack. Physical access technique fused with network technique. Social engineering fused with malware delivery. These cross-domain combinations are where the most novel threats live because most researchers work in silos.
Engine 4 — Evasion Evolution:
Takes any existing attack and evolves its evasion layer. Finds new ways to hide the same attack from: antivirus, IDS/IPS, SIEM correlation rules, EDR behavioral detection, network monitoring, log analysis. Generates attacks that achieve the same goal while systematically avoiding every known detection method.
Engine 5 — Protocol Abuse:
Analyzes legitimate network protocols and finds new ways to abuse them. DNS, ICMP, HTTP/2, QUIC, Bluetooth LE, mDNS, SNMP — finds covert channels, timing attacks, data exfiltration methods hidden inside legitimate protocol traffic. Some combinations have never been documented.
Engine 6 — Living Off the Land Expansion:
Takes the LOLBAS and GTFOBINS databases and finds new combinations of legitimate system tools that together achieve malicious outcomes. No malicious code — only tools already on the system. These are the hardest attacks to detect because everything used is legitimate and expected.
Engine 7 — Payload Polymorphism:
Takes any payload and generates infinite unique representations that all behave identically. Same function, different encoding, different obfuscation, different structure every time. Generates variants that all achieve the same thing but none share any signature with each other or with the original.
Step 4 — Claude AI Evaluation:
Every mutation goes through Claude for evaluation:

Technical validity — would this actually work on a real Linux/Windows system
Novelty assessment — how different is this from anything in the MITRE ATT&CK database or public exploit databases
Detection prediction — which security tools would likely catch this and which wouldn't
Gap filling — if a mutation has a logical gap, Claude writes the missing code to complete it
Optimization — Claude refines the generated code to be more reliable and effective
Implication analysis — what could a sophisticated attacker do with this technique
Defense generation — Claude immediately generates the detection rules and defensive measures
