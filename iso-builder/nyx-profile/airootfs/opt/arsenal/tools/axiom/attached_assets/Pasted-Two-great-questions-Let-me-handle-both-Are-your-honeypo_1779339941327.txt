Meli — Bugs Fixed Locally, Need Permanent Fixes in Repo
I had to manually patch four issues on my local install tonight to get Meli's ingest daemon working. Please commit equivalent fixes to the main repo so fresh installs don't hit these problems.
Bug 1: pyproject.toml declares a non-existent build backend
pip install -e . fails with:
BackendUnavailable: Cannot import 'setuptools.backends.legacy'
setuptools.backends.legacy is not a real build backend. The pyproject.toml [build-system] section should likely be:
toml[build-system]
requires = ["setuptools>=61.0", "wheel"]
build-backend = "setuptools.build_meta"
Please fix the build backend declaration so the standard install path actually works.
Bug 2: install.sh never installs the meli package into the venv
After running the installer, /opt/meli/venv/ had all dependencies but the meli package itself was not installed. python -m meli failed with No module named meli.
I worked around this by replacing /usr/local/bin/meli with a launcher that sets PYTHONPATH:
bash#!/usr/bin/env bash
export PYTHONPATH=/opt/meli/app${PYTHONPATH:+:$PYTHONPATH}
exec /opt/meli/venv/bin/python -m meli "$@"
Please update install.sh so it either:

Successfully runs pip install -e . against the source (after Bug 1 is fixed), OR
Uses the PYTHONPATH launcher pattern by default

Also please add Environment=PYTHONPATH=/opt/meli/app to the systemd unit files (meli.service and meli-ingest.service) so the services work without manual editing.
Bug 3: datetime JSON serialization crash on every event
When events were ingested, the processor crashed with:
Object of type datetime is not JSON serializable
Location: /opt/meli/app/meli/ingest/processor.py, the json.dumps(normalized) call.
Fix: pass default=str to that json.dumps call. Already patched locally — needs to be in repo.
Bug 4: GeoIP "log once" patch produced invalid Python syntax
A string-replace patch left geolocation.py with this broken code:
pythonif not _readers_loaded:
    _readers_loaded = True
    if True:          # <-- this line had no indented block after it
    import geoip2.database
    ...
This causes expected an indented block after 'if' statement on every event processed.
I removed the spurious if True: line. The intent of the patch (log GeoIP unavailability once instead of per event) is fine, but the implementation needs to not introduce a dangling if. Either:

Remove the if True: line entirely (what I did locally), OR
Implement the one-time logging using a proper flag check pattern without the nested if True:

Bug 5 (separate from above): No log directory created by installer
The systemd unit declares StandardOutput=append:%h/.local/share/meli/logs/ingest.log, but ~/.local/share/meli/logs/ does not exist after install. Systemd silently refused to redirect logs until I created the directory manually with mkdir -p.
Please have install.sh create:

~/.local/share/meli/logs/
~/.local/share/meli/geoip/ (so the GeoIP downloader works without manual prep)
~/.local/share/meli/cache/
~/.local/share/meli/exports/
~/.local/share/meli/reports/

Bug 6 (UX): "Add Honeypot Source" button silently failed when daemon was down
When the meli-ingest daemon was crashing in a restart loop, clicking "Add Honeypot Source" in Settings did nothing — no dialog, no error message. The button appeared dead.
The UI should detect when the ingest daemon is unhealthy and either:

Display a clear error: "Cannot add honeypot source — ingest daemon is not running. Click here to see logs / restart."
OR show a connection status indicator somewhere visible (top bar?) so the user knows the backend is broken before they try to use it.
