# NYXUS — Login screen & boot splash (rev 2026-07-09)

How the lock screen, the greeter and the Plymouth splash are wired,
why the old login screen failed, and how to enable everything on an
installed system.

---

## 1. Lock screen (hyprlock · Prism HUD)

`~/.config/hypr/hyprlock.conf` (ships in skel) is themed to the
nyxus-home HUD language: ink-black clock card with a 1px neon hairline
+ 2px neon top rule, Orbitron ExtraBold numerals, small-caps mono
labels, Caveat "welcome back, $USER" flourish, prism-gradient input
rim, now-playing card (MPRIS via `nyxus-lock-art` / `nyxus-lock-track`)
and the cached `nyxus-weather-line`.

Accent discipline: primary/secondary neon rides
`~/.config/hypr/hyprlock-accent.conf`, generated by
`nyxus-apply-accent` §3. The template emits:

| token | meaning |
|---|---|
| `$nyxus_accent_rgba` / `_glow` / `_dim` / `_faint` | primary accent at α 1.0 / 0.45 / 0.75 / 0.20 |
| `$nyxus_accent2_rgba` / `_glow` / `_dim` | secondary accent |
| `$nyxus_accent_r/g/b` | legacy decimal channels (kept for old configs) |

Fixed LOCKED palette constants (gold `#ff8b26`, red `#ff4d6b`, cyan
`#66efff`, white-off `#e8edf5`, card ink `#07050e`) are hardcoded by
design and never re-skin.

Validation without locking the session: hyprlock has no dry-run, but
run against a dead Wayland display it fully parses the config before
failing to connect — config errors print first:

```sh
WAYLAND_DISPLAY=dead hyprlock --config ~/.config/hypr/hyprlock.conf
# "Config error in file …" lines = broken; only the
# "Couldn't connect to a wayland compositor" assert = parse-clean.
```

## 2. Boot splash (Plymouth · GALAXY EYE)

The signature splash is the **NYXUS eye-mosaic** — a cosmic eye with a
spiral-galaxy iris and the wordmark glowing in the pupil (history:
`8c7672e` "boot-splash: NYXUS eye mosaic backgrounds for Plymouth +
GRUB"; kin to the 5K `nyxus-eye-mosaic.png` wallpaper of `363dc35`).

Theme: `/usr/share/plymouth/themes/nyxus/` — `nyxus.script` rev r2
draws the eye full-bleed (cover-scaled) over `#05010d` ink with a thin
purple→cyan prism progress bar, LUKS prompt + boot-message handling.
`logo.png` stays in the dir for tooling compat but is no longer drawn.

Wiring on the ISO (already in place):

- `packages.x86_64` → `plymouth`
- `airootfs/etc/plymouth/plymouthd.conf` → `Theme=nyxus, ShowDelay=0`
- `airootfs/etc/mkinitcpio.conf.d/archiso.conf` → `plymouth` hook (live)
- `airootfs/etc/mkinitcpio.conf.d/10-nyxus-plymouth.conf` → hook for
  installed systems

On an **installed system** (or this dev machine, where the theme +
plymouthd.conf are already present but the hook/cmdline are not):

```sh
sudo nyxus-plymouth-install   # adds plymouth hook after kms,
                              # appends `quiet splash` to /etc/kernel/cmdline (UKI),
                              # rebuilds via mkinitcpio -P.
# reversible: restores from *.nyxus-bak + rerun mkinitcpio -P
```

`nyxus-plymouth status|test|set-theme|…` manages it afterwards.

## 3. Login screen (greetd · themed regreet chain)

### Why the old one failed

The airootfs shipped **two rival display managers**: a greetd
config + `display-manager.service → greetd.service` alias, *and* an
SDDM theme/conf. `customize_airootfs.sh` (and `nyxus-postinstall`) ran
`systemctl enable sddm.service` — **but `sddm` was never in
`packages.x86_64`**, so the enable silently no-oped — and then
`systemctl disable greetd.service`, which removed the alias. Net
result: `graphical.target` with **no display manager at all** → black
screen, log in from a TTY. (The May 2026 commit `17f4436` had also
made the bake compile tuigreet from source — a network+cargo build
inside the chroot — as the "polished" layer; brittle, and now
unnecessary since `greetd-tuigreet` is packaged.)

### The new stack (all official Arch packages)

- `greetd` + `greetd-regreet` + `cage` + `greetd-tuigreet`
  (`packages.x86_64`); `greetd.service` enabled by
  `customize_airootfs.sh` (live) and `nyxus-postinstall` (installed);
  `display-manager.service` alias ships in airootfs.
- `/etc/greetd/config.toml` → `default_session` runs
  **`/usr/local/bin/nyxus-greeter`**, the defensive wrapper.

Fallback chain (each layer only if the previous is missing or crashes
within 5 s of start; a layer that crashes twice in one boot is demoted
for the rest of the boot):

1. **regreet under cage** — the themed NYXUS login screen.
   `/etc/greetd/regreet.toml` (galaxy-eye backdrop
   `/etc/greetd/nyxus-eye.png`, dark GTK, clock, greeting
   *"welcome back, operator"*) + `/etc/greetd/regreet.css`
   (HUD card language: ink surfaces, dashed neon hairline + solid neon
   top rule, mono small-caps buttons, green neon entry focus).
2. **tuigreet** — packaged TUI greeter, prism `--theme` palette.
3. **agreety** — greetd's built-in text greeter.
4. **direct Hyprland** — box stays usable with no greeter at all.

Live-ISO extra net: `[initial_session]` autologs the `nyx` user into
Hyprland on the first greetd start of a boot. `nyxus-postinstall`
**strips that block on installed systems** so real installs always
prompt.

### Enabling on an installed system

Nothing manual: `nyxus-install` → `nyxus-postinstall` enables
`greetd.service` and strips the autologin block. By hand:

```sh
sudo systemctl enable greetd.service      # sole DM — never alongside another
sudo sed -i '/^\[initial_session\]/,/^\[/{/^\[initial_session\]/d;/^\[/!d}' \
    /etc/greetd/config.toml               # remove live autologin
```

Do **not** enable greetd on the NYXUS dev machine — its daily login is
cosmic-greeter; the stack above ships dormant in the repo/ISO only.

### SDDM leftovers

`airootfs/usr/share/sddm/themes/nyxus/` (QML theme),
`/etc/sddm.conf.d/*` and the `nyxus-loginscreen` helper remain in the
tree but are **dormant** — sddm is not in `packages.x86_64` and
`verify-profile.sh` fails the build if it ever appears. They can be
revived only by deliberately switching DMs.
